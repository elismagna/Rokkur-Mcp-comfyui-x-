# Local reliability and interface upgrade — 2026-10-07

This upgrade prioritizes controls that actually reach the installed Wan VACE workflow,
clear render review, and accurate timing on Elis's RTX 3070.

## Using the upgraded studio

1. Open **New video**. Pick a file from the media folder or upload it. The source preview
   shows its dimensions and duration.
2. Describe the intended style and the source subject. For a look that conflicts with the
   saved photographic defaults, uncheck **Apply my saved global look**.
3. Upload an appearance reference if you have one. Otherwise **Use the first frame of each
   shot** is the default. Choose **prompt and motion guide only** to disable the automatic
   reference. An uploaded reference takes precedence over that fallback.
4. Start with **RTX3070 QUALITY** for a meaningful quality comparison. PREVIEW is smaller
   and uses 8 steps. It is useful for checking the pipeline, not predicting final quality.
5. Under advanced controls, use a fixed seed when comparing source structure strength,
   steps or prompt guidance. Higher values are not always better.
6. Review the assembled output and individual attempts on the project page, including when
   QC stops the project. **Applied render settings** shows actual values recorded for each
   attempt. **What the last repair changed** distinguishes supported changes from controls
   that this workflow cannot apply.
7. At the repair limit, review before choosing another round, checking quality again, or
   keeping the current renders.

Text and settings are restored after a creation error. Uploaded files must be selected
again because browsers do not allow restoring file inputs. Automatic refresh pauses while
a video plays, a form is being edited, or details are open.

## What changed

- Appearance references are imported, resolved to a worker-readable file, uploaded to
  ComfyUI and connected to WanVaceToVideo. Automatic source references use a separate
  optional LoadImage node. Disabling references removes that node and its link.
- Source videos are padded to a valid Wan 4n+1 frame count. Only the intended number of
  frames is delivered. Encoder frame rate is explicit; this fixes a missing final frame /
  incorrect MP4 duration observed with the installed container FFmpeg.
- OOM fallback also respects the smaller profile's dimensions and frame budget. It lowers
  sampling frame rate to preserve the full shot, and assembly aligns cuts to the overall
  timeline. Old normalized clips use a different cache name so they are not reused.
- Source structure, seed, steps, CFG and negative prompt are wired from the form/API to
  the manifest and workflow. API render records now include their effective parameters.
- Creative Director receives up to four source images when vision is available. Shot
  stories merge by shot ID, so reordered model output cannot attach a subject to the
  wrong timing. Vision responses must include observed subject/background descriptions;
  missing observations trigger validation/fallback rather than being silently accepted.
  The photography pass does not receive the story's guessed anatomy when it has an image.
  Rule fallback includes a visible warning when it lacks source observations.
- Wan repairs can change CONTROL_STRENGTH and the seed. Unmapped style strength, identity,
  pose and depth settings are excluded from repair changes and reported as unavailable.
  These repairs remain bounded experiments, not a guarantee of improved images.
- QC handles low-motion footage without relying on noisy correlations, penalizes frozen
  output of moving footage, rejects substantial frame loss, and flags likely edge-only
  images for review. Identity, anatomy and prompt fidelity remain unmeasured.
- Missing workflows, remote-only profiles and insufficient configured VRAM are refused
  before jobs are created. HYBRID_MAX has no remote executor and FUTURE_24GB is unavailable
  on the current 8 GB configuration.
- A shared dark/light layout, guided creation form, reference previews, comparison players,
  safe refresh, duplicate-submit prevention, clearer capability status, keyboard focus and
  responsive layouts apply across the existing dashboard.
- Tests now refuse a database whose name does not end in _test. Test databases remain
  separate from the production rokkur database. Media is excluded from git and Docker builds.

## Tested on Elis's workstation

Final verification on 2026-10-08: **199 tests passed**, `ruff check src tests` and `mypy src`
passed. The suite uses real FFmpeg and isolated Postgres with fake external APIs. The
separate real-model checks below cover the installed Ollama and ComfyUI services.
The rebuilt API and worker are deployed at http://127.0.0.1:8400/ui. Ten live pages and
video range requests passed after deployment; the existing project history was retained.

The real acceptance sample is 8.633–11.067 seconds of the existing source, the shot with a
green frog held above water and bubbles. It is a section of the monkey video, not a shot
with the monkey's face fully visible.

- Qwen3.5:9b ran both director passes with source vision in 18.5 seconds. It recognized the
  frog, but mistook the fingers for a shell. Follow-up tests found optional observation fields
  were being skipped, which is now prevented by a separate required vision schema. With
  required fields and independent observation it still misidentified the fingers as a shell.
  This remains a real model limitation; do not claim the agent fully understands the scene.
- Wan VACE 1.3B rendered 576×320, 41 generated frames, 39 delivery frames, 20 steps,
  CFG 6 and seed 73529. No additional models were downloaded.
- Source strength 0.85 plus a source-frame reference produced filled, colored surfaces
  with a clay-like appearance in about 82 seconds including preparation/download.
  It still distorted the frog and changed motion. QC was 5.29/10: FAIL.
- A comparison with strength 1.15 took about 100 seconds and worsened visible anatomy.
  Its motion metric improved, but overall QC fell to 5.19/10. This is evidence against
  simply increasing guidance for every problem. The default remains 1.0.
- The second run verified the timing fix: exactly 39 frames at 16 fps, 2.4375 seconds.
- Browser checks exercised actual source/reference previews, advanced controls, disabled
  profiles, draft recovery, dark/light switching, successful form creation and all eight
  main navigation destinations. At 390 px width there was no horizontal overflow and
  no browser JavaScript errors.

Local acceptance artifacts are under data/validation/upgrade_2026-10-07/ (git-ignored).
They are test renders, not approved final videos. The supplied outline-heavy output and
these renders use different prompts/settings, so this is not a controlled speed or
quality benchmark and does not establish a numerical “10×” improvement.

## Remaining work and limits

- Real character fidelity, hand interactions and temporal consistency still need tuning.
  Check actual video frames, not only QC averages. A higher QC subscore can accompany
  worse-looking anatomy.
- The real Google/YouTube path is still unverified. Automated publishing tests use a fake
  service; nothing was uploaded during this work.
- Discovery, comments, analytics and external Rökkur/Odysseus integrations remain
  unimplemented and are labeled accordingly.
- Existing finished exports are not rerendered automatically. New controls apply to new
  renders. Old attempt records may lack reference details.
- The existing Ape project is at its total 40-render budget, separate from the per-project
  repair-round allowance. It remains stopped. The current UI still needs a dedicated flow
  for resolving that total budget; repeatedly pressing Resume will not resolve it.
- The edge-only heuristic flags synthetic contour cases, but did not flag the supplied
  outline-heavy render. That render still failed on flicker/layout. This detector needs
  further real-video calibration and must not be treated as comprehensive.
